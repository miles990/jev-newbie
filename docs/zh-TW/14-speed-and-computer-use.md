# 平行判斷、速度與電腦操作

Jev 的實用強項之一，是**對同一份資料一次回答多個獨立問題**。例如看一則訊息，同時判斷「要回覆嗎」「是不是邀約」「有期限嗎」。後續動作由程式決定。參考[官方 fan-out 說明](https://docs.typesafe.ai/patterns/fan-out)。

## 兩種平行，要分清楚

- **一個請求、多個問題**：共用同一份輸入，減少重複傳送和網路往返。
- **多個請求同時處理**：例如同時分析四則訊息。本專案 CLI 預設最多四筆併發；受 API 限流、網路與輸入大小影響。

如果後一題需要前一題的結果，就不能直接當作獨立問題一起問。更多問題也會增加用量；平行不等於免費。

## 本機實測，2026-09-19

`examples/js/latency.mjs` 使用 `jev-1.13.0`，三次暖機、五輪比較、最後四次併發，共 37 次 API 呼叫。

| 方法 | 實測時間 |
| --- | --- |
| 一次問一題 | 中位數 257 ms |
| 一次問四題 | 中位數 258 ms |
| 四題分成四次依序問 | 中位數 1,018 ms |
| 四個請求同時送出，每個四題 | 整批 638 ms（僅一批） |

[原始測量資料](../research/latency-2026-09-19.json)。這是短文字、小樣本的端到端測量，不是準確度比較、服務保證或與其他模型的 benchmark。也無法從兩次請求的時間推斷伺服器是否快取。CLI 沒有通用 API 快取；只有 usefulness 範例提供明確的離線 `--reuse`。

## 電腦操作怎麼用？

[Jev-cu](https://github.com/Sac-Y/Jev-cu) 的流程是：

```text
讀取介面文字 → 列出可操作元素 → Jev 選元素與動作 → 本地規則檢查 → 執行 → 重新觀察
```

Jev 不負責截圖辨識或實際點擊。這個工具使用 macOS 無障礙資訊與 Codex Computer Use；需要相應的桌面權限。目標、動作、完成狀態等可一起問，但下一次操作要根據更新後的介面決定。有限選項能限制動作範圍，不能保證安全或一定選對。

本次 Jev-cu 離線單元測試 18/18；用 API 判斷既有介面快照 12/12 選對。後者只是快照選擇測試，尚未證明完整桌面任務的成功率或提速。

## 選擇也能組成新內容

[Sprite Fusion 的關卡實驗](https://www.spritefusion.com/blog/generating-game-level-in-real-time-with-jev)把地形拆成寬度、間距、高度、表面種類等選項，同一請求取得多個選擇後，由遊戲程式組成下一段地形。作者記錄五次呼叫 319–375 ms；不是本專案重測，也沒有傳統演算法對照。

這種方式適合有明確組件與限制的組合內容。各題個別合理，不代表合起來一定能通關；程式仍須檢查可達性、碰撞與難度。素材、動畫和遊戲程式本身並不是 Jev 產生的。

更多用途與來源：[案例研究](17-use-case-research.md)。
