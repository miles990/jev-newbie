# 收斂閉環：LLM 提案，Jev 量測，程式碼決定

上一篇把 Jev 放在 LLM 的前面、裡面、後面。這一篇把圈閉起來：LLM 的輸出餵給 Jev，Jev 的數字餵給 LLM，迴圈自己停下。讓它停下的從來不是 LLM，也不是 Jev，而是程式碼從 Jev 的型別化答案算出的一個純量指標，加上強制收斂的規則。

## 為什麼 Jev 適合當迴圈的量尺

- **每一輪重新對整批打分幾乎不花錢。** 十二則訊息、每則一題、三輪：不到一美分。你不必抽樣，也不必猜上一次改動有沒有幫助。
- **它一致。** 同一輸入跨輪得到同一標籤，指標的變化反映的是提案，不是雜訊。
- **它型別化。** 指標是 `count(other) / n` 或 `mean(confidence)`，不是解析散文。
- **它不會被說服。** LLM 提案，但不替自己的作業打分。

## 三種會收斂的迴圈

### A. 擬稿 → 檢查 → 修改（已在 `jev-then-llm.mjs`）

LLM 寫回覆；Jev 回答「有回答問題嗎」「有過度承諾嗎」；沒過的檢查被點名回饋；重試一次；然後交給人。收斂規則：所有檢查過門檻，或重試上限。

### B. 分類法探索（`llm-then-jev-loop.mjs`）

從一份很差的類別清單開始。Jev 分類全部；落在 `other` 或信心低於 0.6 的是未知堆。LLM 看那堆，提出**一個**新類別。程式碼加進去，Jev 重新分類，重複。

真實執行，`jev-1.13.0`，2026-09-19：

```text
round 1  categories=3  other-rate=58%  mean-conf=0.95
  + LLM proposed: schedule: upcoming appointments, events, or travel with a specific time
round 2  categories=4  other-rate=17%  mean-conf=0.98
  + LLM proposed: shopping: Shopping messages: promotions, sales, and purchase inquiries
round 3  categories=5  other-rate=0%  mean-conf=0.99
✓ converged: other-rate 0% ≤ 10%
```

三輪，58% → 17% → 0%。注意有一個可議的歸併：「媽問電鍋是哪個牌子」被放進 `shopping`。迴圈最佳化的是它被給的指標；那個位置是不是*你*要的，是黃金測試集的問題（第 7 課），這就是為什麼收斂後的分類法上線前仍要有人看一眼。

### C. 問題探索（官方 autoresearch cookbook）

LLM 提出候選*問題*；Jev 對已標資料回答；程式碼量哪些問題能預測標籤；LLM 提出更好的。同樣的形狀，往上一層：被改進的東西是 Jev 的問題本身。

## 收斂規則，全部在程式碼

1. **一個純量指標**，來自 Jev 的答案：other 比率、黃金測試集準確率、平均信心、檢查通過率。
2. **一個目標**（`other-rate ≤ 10%`、`所有檢查通過`），一達到就結束。
3. **單調接受。** 保留最佳一輪的狀態。讓指標變差的提案丟棄，絕不套用。
4. **無進步就停。** 一輪沒有改善最佳值就停，不讓 LLM 空轉。
5. **上限**：輪數上限，以及會長大的東西（類別、criteria、prompt 長度）的上限。
6. **套用前驗證 LLM 的提案**：形狀、唯一性、長度。不能用的提案結束迴圈，而不是污染狀態。
7. **出口有人。** 不論收斂或停止，結果連同指標與 log 先給人看，再使用。

## 陷阱

- **過擬合檢查器。** LLM 看到的如果就是 Jev 打分的那些項目，它可以提出只適合那十二則、別的都不適合的類別。留一組 Jev 打分但 LLM 從沒看過的資料，兩個數字都報。
- **震盪。** 兩個互相抵銷的提案。單調接受加無進步即停讓它不可能發生。
- **Jev 的字面性。** LLM 寫的類別描述會變成 Jev 的 criterion；模糊的描述產生模糊的機率。限制描述長度，在 prompt 裡要求區別性。
- **指標被鑽。** `other-rate` 可以靠把所有東西吸進一個大類別做到 0%。搭配 `mean confidence` 與黃金測試集。

## 所有事物都能放進這個迴圈嗎？

不能。照上面的規則，迴圈一定會*終止*；但要*收斂到有用的結果*，四個條件都得成立：

1. **目標可以用文字判斷。** Jev 得能從字面回答「這樣比較好嗎」。類別、相關性、語氣、草稿有沒有回答問題：可以。程式碼能不能編譯、數字對不對、圖片看起來對不對、某件事在世界上是否為真：不行。那些需要別的裁判（編譯器、測試、計算機、感測器、人），迴圈應該繞著那個裁判建，Jev 只判文字的部分。
2. **指標與提案者獨立。** LLM 如果看得到 Jev 打分的全部項目，它可以滿足評分者而不滿足你。留一組看不到的資料，報那個數字。
3. **提案空間真的能推動指標。** 讓 LLM 改寫類別描述的迴圈能修好模糊的類別；它修不好一個問錯了的問題。有些迴圈需要的是人去改問題，不是 LLM 去改答案。
4. **「收斂」不等於「正確」。** 迴圈在數字不再動的時候停下。那個數字是你選的代理指標，古德哈特定律適用：分類法迴圈做到 0% `other`，部分靠把家人訊息塞進 `shopping`。黃金測試集、第二個指標（平均信心）、出口的人，才是把「指標不動了」變成「這是對的」的東西。

| 任務 | 適合迴圈？ | 為什麼 |
| --- | --- | --- |
| 把類別清單長到很少項目是 `other` | 適合 | 可判、重打分便宜、單調 |
| 改一段回覆直到 Jev 的檢查通過 | 適合 | 檢查是文字的；通常兩輪夠 |
| 改一個 Jev 問題直到它能預測標籤 | 適合，要有留出集 | 官方 autoresearch cookbook |
| 調 prompt 直到 eval 通過 | 適合，要有真的 eval | 同樣的迴圈；文字型 rubric 可讓 Jev 當評分者 |
| 讓程式碼通過測試 | 不適合以 Jev 當裁判 | 測試才是裁判；Jev 只能分流失敗 |
| 讓數字、日期、加總正確 | 不適合 | Jev 不會算 |
| 讓圖片或影片正確 | 不適合 | Jev 看不到 |
| 決定法律、醫療、安全問題 | 終止後交人 | 迴圈能縮小範圍；不能決定 |

所以誠實的說法是：**品質可以用封閉的文字判斷來衡量的東西，都能便宜地迴圈到收斂；其餘的需要自己的裁判，Jev 站在旁邊，不取代它。**

## Jev → Jev 與 LLM → LLM：同種互接什麼時候值得

互接是成本。只有當第二次呼叫擁有第一次沒有的東西時才值得：新的 state、依賴第一次答案、或不同的角色。

**Jev → Jev。** Jev 回的是數字與標籤，不是文字，所以「Jev → Jev」是指第二次請求的 `state` 包含第一次的答案、或程式碼因為那些答案去抓來的東西。值得的情況：

| 形狀 | 為什麼需要第二次請求 | 官方參考 |
| --- | --- | --- |
| 階層式分類 | 下一層的選項取決於上一層的選擇 | hierarchical_classification cookbook |
| 先全部排序，再細讀前幾名 | 第一階段對標題便宜地排；第二階段看三個候選的全文 | skill_suggestion cookbook |
| 先抓證據，再判斷 | 第一個答案決定要取哪些證據；第二次判斷它 | citation_check、rerank cookbook |
| 自我一致性 | 同一判斷換句話問或選項換序再問；不一致的項目標出來 | consistency_noul／consistency_choice cookbook |

不值得的：同一題問兩次「再確認一下」（沒有新資訊）；為了合併判斷而串接（在程式碼合併，免費）；把 Jev 自己的機率當文字餵回去（它對數字弱）。預設永遠是一次請求、多題平行；只有當某個答案需要用來建構下一個 state 時才發第二次。

**LLM → LLM。** 規劃者 → 執行者、擬稿者 → 編輯、生成者 → 批評者、兩個 agent 辯論。值得的情況：第二次呼叫角色不同且上下文全新（不繼承第一次的定錨）、模型不同（便宜擬稿、強的審查）、或任務真的可以分解。不值得的是當*評審*：LLM 替另一個 LLM 打分會共享盲點、會被說服、成本跟被評的工作一樣高、而且很少自己收斂。那個位置屬於 Jev 或程式碼。實務上站得住的模式是**每個生成階段用 LLM，階段之間放 Jev 或決定性檢查，由程式碼決定要不要繼續**：擬稿（LLM）→ 檢查（Jev）→ 改寫（LLM）→ 檢查（Jev）→ 送出或升級（程式碼）。

所以：答案會改變你下一題問什麼時，Jev 接 Jev；角色不同時，LLM 接 LLM；有型別化評審可用時，永遠不要讓同一種東西替自己打分。

## 通往哪裡

迴圈 B 是 `kind` 問題從三個類別長成你的資料真正擁有的類別的方式。迴圈 A 是產品裡每一個 LLM 輸出取得關卡的方式。迴圈 C 是問題本身變好的方式。三者都跑在第 1 到 8 課的相同基本型別上；唯一的新想法是：停止條件是 Jev 產生、程式碼檢查的一個數字。
