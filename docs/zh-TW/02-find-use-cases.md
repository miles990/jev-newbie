# 找到適合自己的用法

先從生活或工作中反覆出現的判斷開始，而不是先找程式碼來替換。

| 你想做的事 | Jev 可以判斷 | 程式或人負責 |
| --- | --- | --- |
| 整理訊息 | 類別、需不需要回覆、急迫程度 | 顯示、提醒、實際回覆 |
| 整理收藏 | 和目標是否相關、適合哪個主題 | 收集網頁、儲存、排序 |
| 選學習資源 | 適合新手嗎、有練習嗎 | 查證內容、設定偏好 |
| 檢查草稿 | 是否回應問題、有沒有未支持的承諾 | 修改與決定是否送出 |
| 操作介面 | 從已知按鈕中選下一個 | 讀取畫面、檢查規則、實際點擊 |

同一則訊息的多個問題可合併請求；很多則訊息則是多筆請求的批次處理。參考 [官方用例地圖](https://docs.typesafe.ai/concepts/use-case-map)找方向，不能把用例清單當成已驗證的效果。

對開發者而言，關鍵字分類可能值得比較，但明確的 ID、狀態碼、授權或穩定查表通常應保留。先用已標答案的資料比較現有方法和 Jev，再決定是否替換。

要將篩選結果接到下一步：

```sh
node bin/jev.mjs filter examples/cli/inbox-messages.txt "Does the sender expect me to reply?" --only-kept > kept.txt
node bin/jev.mjs run examples/cli/inbox.questions.json kept.txt
```

預設 `filter` 顯示所有項目與分數；只有 `--only-kept` 才輸出通過的原文。沒通過任何項目時，輸出是空檔；下一步應略過，而不是當作有效批次。

保留「其他」與覆核流程。低信心可能代表模糊或陌生，也可能沒有；不是未知偵測保證。
