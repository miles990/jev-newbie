# Monte Carlo 搭配 Jev

Jev 的答案是校準過的機率，這正是 Monte Carlo 方法要的輸入。搭配方向只有一個：**Jev 對每個項目給一次機率；程式碼想抽多少次就抽多少次。** 絕不反過來，因為 Jev 不會抽樣、計數、加總。

## 它換來三件事

**1. 政策模擬。** 從 Jev 的機率抽一萬次每則訊息的「真實」結果，套用門檻政策，數它多常刪掉真的訊息或漏掉回覆。你得到的是分布，不是單一猜測，而且能在同一批抽樣世界上比較兩個門檻。

**2. 期望成本決策。** 不用固定門檻，給每個動作一個成本，每個項目挑期望成本最低的：`E[刪除] = (1 − p_scam) × 刪掉真訊息的代價`，以此類推。門檻消失了，剩下一張可以跟同事吵的成本表。

**3. 黃金測試集的信賴區間。** 對已標案例做 bootstrap，看你的「8/8」到底承諾了多少。八筆案例的區間很寬，腳本會直說。

## 執行結果

`examples/js/monte-carlo.mjs`，對十二則訊息（收件匣加四則刻意模糊的）跑一次 Jev，然後用有種子的亂數做純算術，同樣的機率重跑得到同樣的數字。2026-09-19 錄，`jev-1.13.0`：

```text
Policy simulation over 10000 sampled weeks of this inbox:
  delete if p(scam)>0.8,  reply if p(reply)>0.7: wrong deletes/wk=0.000, missed replies/wk=1.17, replies owed p50/p90=5/6
  delete if p(scam)>0.95, reply if p(reply)>0.5: wrong deletes/wk=0.000, missed replies/wk=1.16, replies owed p50/p90=5/6

Expected-cost decisions (minutes of pain):
  ignore  E=  2.2  (delete 34.0, reply 2.7, ignore 2.2)  Package arriving today. Track it here: b…
  reply   E=  1.8  (delete 37.6, reply 1.8, ignore 5.8)  這個月房租記得匯，謝謝。（來自未儲存的號碼）
  delete  E=  0.0  (delete  0.0, reply 1.7, ignore 1.0)  帳號有異常登入，請回撥 0800-123-456 確認身分。
```

兩個誠實的觀察。刪除門檻在這個收件匣上完全沒差：Jev 覺得可能是詐騙的每一則都是 0.99 以上，其餘全在 0.15 以下，所以 0.6 到 0.95 之間的任何政策都沒刪過真訊息。Monte Carlo 只在機率真的落在中間時才有話說；這裡是「要不要回」那一題，三則訊息落在 0.15 到 0.45 之間，在每個政策下都製造約每週一次的漏回。這才是真正的發現：不是「哪個門檻」，而是「不確定性住在回覆那一題，黃金測試集該花在那裡」。

## 其他適合搭配的地方

- **成本本身不確定時的錯誤代價。** 成本數字本身是分布時（漏回一封到底多糟？），把它也抽樣。
- **決策迴圈。** 社群的遊戲與無人機專案裡，Jev 的 `choice` 分布當政策先驗，程式碼跑 rollout。Jev 300 毫秒的速度，配合狀態指紋與快取，每個決策幾百次葉節點評估可以，幾百萬次不行。
- **強健性估計。** Jev 對相同輸入幾乎決定性，所以對*同一個*輸入抽樣是浪費。改抽*state*：換句話問、選項換序、拿掉一個欄位，看答案動多少。這是對輸入做 Monte Carlo，也是量測一個問題有多脆弱的誠實方法。

## 不要做的事

- 不要叫 Jev 模擬、計數、加總。那一次之後的全部是程式碼。
- 不要把 Jev 的機率當成一次隨機抽取：它是機率的點估計。隨機性屬於你抽樣的世界，不屬於模型。
- 不要在沒有黃金測試集的情況下報 Monte Carlo 結果。校準讓抽樣有意義；黃金測試集告訴你校準在你的資料上成不成立。
