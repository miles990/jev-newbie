# 可靠性：最可靠的 Jev 用法

Jev 的型別化輸出保證的是*介面*，不是*真相*。可靠來自你怎麼問、怎麼設關卡、怎麼看。十個習慣，按你會遇到的順序。

## 1. 封閉問題，但留出口

每個 `choice` 都有 `other` 或 `none`。每個 `noul` 是一個字面的條件，不是感覺。`score` 的每一級描述具體情境，不是形容詞。如果你寫不出「第 2 級長什麼樣」，那還不是一個 score 問題。

## 2. 一題一個判斷

「這是不是又急又跟帳務有關？」是兩題。拆開，在程式碼裡合併。同時權衡多個因素的問題會回你一個糊掉的機率。

## 3. 規則寫進 instructions，不要留在腦子裡

Jev 逐字讀。當錯的答案讓你想解釋「我的意思是……」，那段解釋就是 instructions 缺的另一半。把邊界案例寫進 criteria。

## 4. 先有黃金測試集，再有門檻

自己標二三十筆真實資料。跑 `jev check questions.json cases.jsonl`。看那些沒中的：通常一半是你的標籤本身模糊，這也是發現。之後才定門檻。

## 5. 三段信心，不是一刀切

- 高：自動執行。
- 中：標成 `review`，顯示但不決定。
- 低：拒絕，或交給人或 LLM。

分界在哪取決於錯的代價。要花更多的動作（升級、阻擋、叫人）門檻要比花更少的高。

## 6. 關卡失敗放行，評審失敗安靜

沒有 key、逾時、429：呼叫照常進行，記一行 log。遇到基礎設施錯誤就阻擋的安全關卡，一週內就會被關掉。先 shadow 模式，再 enforce。

## 7. 用請求雜湊快取

相同 state 加相同問題就是相同答案。把請求做雜湊、快取答案，重跑與 CI 就免費。本 repo 的 `jev` CLI 與每支腳本都這樣做。

## 8. 釘住模型，記錄模型

`jev-latest` 會移動。有門檻的地方釘住 `jev-1.13.0`，並記錄每次回應的 `model` 欄位，升級時就能重跑黃金測試集。

## 9. 算數、日期、查表留在程式碼

計數、四則、日期區間、精確 ID：在程式碼算好，把結果或命名分桶傳給它。Jev 負責需要常識的那一段。

## 10. 每次呼叫都記錄，並且看過

每次呼叫一行 JSONL：state 雜湊、問題、答案、決定、模型、延遲、token。`jev view` 畫出來。機率直方圖堆在中間，表示問題或資料不清楚；集中在兩端，就可以收工。

## 上線前檢查清單

- [ ] 每個 choice 都有 `other`／`none`
- [ ] 每題只有一個判斷
- [ ] 邊界案例寫進 criteria
- [ ] 二十筆以上的黃金測試集達到你要的準確度
- [ ] 三段門檻集中在一個檔案
- [ ] 關卡失敗放行；評審遇錯不阻擋
- [ ] 請求快取開著
- [ ] 模型已釘住並記錄
- [ ] 沒有把算數或日期交給模型
- [ ] JSONL 有寫、也看過一次
