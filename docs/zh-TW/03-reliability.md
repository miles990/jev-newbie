# 可靠性：先測量，再決定

型別保證回答的格式，不保證意思判對。`confidence` 描述分布集中程度，不是已量測的正確率。

1. 一題一個判斷，補充必要背景。開放輸入的分類保留「其他」。
2. 建立有人工標籤的案例，保留邊界、模糊與失敗案例。附帶八筆案例只供教學。
3. 在一批資料上調整問題，另留一批沒參與調整的資料作評估。不要為了全對刪除失敗。
4. 分開統計準確率、覆核率、錯誤放行與錯誤阻擋，依影響選門檻。
5. 模型版本、問題、資料與政策一起記錄。換模型後重測。
6. 依用途設計 API 故障行為。可選的排序提示可退回原流程；授權、付款或刪除的檢查失敗應停止或交人處理，不能一律放行。
7. 設定逾時、併發與有限重試；先只記錄建議，不實際動作，確認效果再整合。

## 本專案實作到哪裡

CLI 有每次嘗試的逾時、批次併發上限、429／529 的有限重試與成功紀錄；它不是正式服務框架。沒有通用請求快取。`stateHash` 只是紀錄用，不會避免下一次 API 呼叫。

第 5 課的 `usefulness.mjs --reuse` 可讀取已存答案，這是明確的離線重算功能。自行加快取時，鍵需包含完整 state、問題、模型版本；資料或版本改變要失效。

來源：[信心與門檻](https://docs.typesafe.ai/confidence)、[API 錯誤處理](https://docs.typesafe.ai/api)。
