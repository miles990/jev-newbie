# 限制與但書

Jev 做不到什麼、哪裡弱、使用上的小字條款。來源：官方 [jaggedness 頁](https://docs.typesafe.ai/model-jaggedness/jev-1.13)、[models](https://docs.typesafe.ai/models)、[legal](https://docs.typesafe.ai/legal)、社群回報，以及我們 2026-09-19 用 `jev-1.13.0` 的實測。

## 硬限制：它就是不做這些

| 限制 | 對你的意義 |
| --- | --- |
| 不生成文字 | 不能摘要、解釋、翻譯、替新類別命名。這些配 LLM。 |
| 只吃文字 | 沒有影像、聲音、影片。先轉成文字或結構化欄位；視覺判斷本身留給視覺模型。 |
| 封閉答案 | `choice` 只能回你的選項之一。一定放 `other`／`none`，否則你在逼它選錯。 |
| 呼叫之間沒有記憶 | 每次請求獨立。它需要知道的都得每次放進 `state`。 |
| 每次請求 64k token，state 加最長一題 32k | 長文件要切塊；跨塊的結果在程式碼裡合併。 |

## 軟限制：它在這些地方不可靠，所以留在程式碼

來自官方 jaggedness 清單，每一條我們都在實測中驗證過：

1. **字面閱讀。** 它回答你寫的字，不是意圖。「又急又跟錢有關」對一則急的停水通知回「否」，正確而無用。拆開複合問題；把邊界案例寫進 criteria。
2. **算數與計數。** 不要叫它加總、數次數、比金額。在程式碼裡數，每個項目問一題是非，答案自己加。
3. **日期與時間。** 它把日期當文字讀。「25 號近嗎」信心只有 0.23，因為它不知道今天幾號。把 `today` 放進 state，或在程式碼算好差距、傳一個命名的分桶。
4. **間接推理。** 多跳推理（「寄件者所屬公司的政策意味著……」）會變差。把相關事實直接放進 state。
5. **又大又雜的 state。** 無關細節降低準確度。只送問題需要的，不要整筆紀錄。
6. **對抗性文字。** 為了操弄模型而寫的內容可以推動機率。測邊界案例；高風險的事不要只靠一個 Noul 當唯一防線。
7. **指令與 criteria 矛盾。** 問題說一套、選項描述說另一套，答案會晃。保持一致。
8. **結構不變量。** 它不保證「是 A」與「不是 A」相加為一，也不保證等級在各項目間用法一致。每個決定只問一種方向；恆等式在程式碼裡強制。
9. **score 的數值精度。** 1.38 不是「往第 2 級走了 38%」；拿它設門檻，不要拿它還原數字。

## 校準：機率承諾了什麼、沒承諾什麼

- 校準是模型在類似訓練集任務、英文上的性質，不是對*你的*資料的保證。相信門檻之前先用黃金測試集量。
- `confidence` 描述的是分布多集中，不是答案對不對。自信的錯答案可能發生，而且長得跟自信的對答案一樣；只有黃金測試集分得出來。
- 幾個同樣可接受的選項會分散機率、拉低信心，不代表答案不好。無害的偏好判斷不必因為低信心而卡住。
- 機率在多次執行間會漂幾個百分點，score 約漂一成。標籤穩定。不要把門檻設在你的資料正好坐落的地方。

## 語言

英文是主要訓練語言，準確度最好。中文可用：我們三十句測試裡中文使用者句子的路由準確度與英文翻譯相當，收件匣黃金測試集 19/19 通過。那是一個小測試，不是保證。用自己的資料測，非英文工作負載要特別注意信心值。問題與選項描述用英文寫，資料本身保持原樣。

## 服務與營運上的但書

- **早期存取。** 發布時靠 waitlist。速率上限（撰寫時 250k token/s、1,200 請求/分）文件明說會動態調整。預期會有 429；退避重試（SDK 與 `jev` CLI 已內建）。
- **別名漂移。** `jev-latest` 會無預警換版。門檻重要的地方釘住 `jev-1.13.0`，並記錄每次回應的 `model` 欄位，升級時重跑黃金測試集。
- **延遲對你不是 150 毫秒。** 官方數字 70 到 500 毫秒；從台灣量端對端 250 到 600 毫秒，社群專案直連量到約 750 毫秒。預算抓半秒。
- **費用。** 只算輸入 token，每百萬 0.042 美元。單次便宜；一百萬筆的批次仍是 10 到 40 美元，看 state 大小。
- **資料處理。** TypeSafe 聲明不用客戶請求與回應訓練；零資料保留條款僅限企業方案。不要送密鑰、憑證或整段對話。只送問題需要的最小 state。
- **工具的 key 處理。** `evaluate setup mcp` 會把 API key 明文寫進 agent 設定檔。知道它在哪；共用機器要輪替。
- **Vercel AI Gateway 與 Cloudflare Workers AI** 用各自的 key 提供 Jev，但 gateway 的回應沒有 `confidence` 欄位；自己從分布算，或用直連 API。

## 設計上的但書：Jev 永遠不該是唯一防線的事

- 安全、法律、醫療、金融的關卡。用 Jev 標記並送人審；硬規則留在程式碼，「否」那一邊要有人。
- 任何需要向使用者解釋的事。Jev 給決定，不會用文字說為什麼。把機率與問題記下來，讓人能說。
- 任何有可計算真值的事。精確 ID、加總、日期區間、schema 驗證：程式碼更便宜、更快、永遠對。

## 值得重複的社群提醒

awesome-jev 的維護者提醒，很多早期專案共用同一套鷹架、commit 歷史很薄；採用前要確認它真的呼叫 API、有可跑的檢查、數字有來源。同樣的標準也適用於這個 repo，所以這裡每段輸出都錄下來並由 `npm run verify` 重跑。
