一般人怎麼找到 Jev 能做什麼

  
不是先想「AI 能做什麼」，而是先在自己的流程裡找三種味道。找到了就把它寫成是非題或選擇題，丟進 playground 看機率，再決定門檻。

  

    
味道一
對字串做 if／else。工具名稱後綴表、關鍵字比對、正規表達式分類。每加一個新案例就要改程式碼的地方。

    
味道二
顯示了但沒有用的自由文字。agent 的訊息、退件理由、使用者輸入。它們被印在畫面上，卻沒有影響任何決策。

    
味道三
散在多處的人工分類清單。同一批東西在六個檔案裡各有一份分組，新增一筆要改六處。

    
然後
寫成封閉問題。是非題用 Noul，單選用 Choice，程度用 Score。先在 playground 貼真實資料看機率分布，再把門檻寫進程式碼，最後像這一頁一樣把每次判斷記錄下來。

  

  
    
    
  • Jev 不會做的：生成文字、看圖片、算數字、比日期。這些留給 LLM、視覺模型與程式碼。
    • 
    
  • 判斷品質怎麼驗：拿二三十筆真實資料，自己先標答案，看命中率與信心分布。本頁的三組實驗就是這樣做的，總費用不到兩美分。
    • 
    
  • 可觀測的最低要求：每次呼叫記下 state 雜湊、問題、答案機率、程式碼的決定與模型版本。有了這份紀錄，才能回頭調門檻，也才能在模型換版時重跑比較。
    • 
  






  
對未知事物做篩選，而不只是對已知分類

  
Jev 的「封閉集合」限制的是答案，不是輸入。輸入可以是從沒見過的工具、訊息、檔案或素材；固定的是你問的那一句話。未知的東西會在三個地方露出來。

  

    
未知輸入 · 固定問題
「這個東西是否符合 X？」不需要事先列舉輸入。本頁的工具路由裡有 24 個對照表從沒見過的名稱，Jev 靠常識判對 22 個。社群的 is-malicious 對未知程式碼問「是否可疑」，jev-guard 對未知工具呼叫問「會不會破壞」，Winnow 對未知工具輸出問「跟目前任務有關嗎」。

    
none 選項 · 平坦分布
新類別會以「都不像」的形式出現。Choice 一定加 none 或 other；答案落在 none、或機率分布平坦、信心低於門檻，就是「這是新東西」的訊號。本頁「陪我一下好嗎」信心 0.35 就是這樣被攔下來的。攔下來的交給人或 LLM 命名新類別，再回頭把新類別加進問題。

    
投機式廣撒 · 特徵側寫
不知道要問什麼，就一次問五十題。一次呼叫的問題數幾乎不影響延遲。對每個未知項目問一整組屬性，得到一個機率向量，程式碼再分群或排序。官方 autoresearch cookbook 甚至讓 LLM 自動提出新問題，用預測誤差淘汰沒用的。

    
用例子取代分類
把已知樣本放進 state，問「新項目像不像其中任何一個」。這是 entity alignment 與 rerank cookbook 的做法：類別不必命名，只要能拿出例子。素材產線裡可以拿十段已接受與十段退件的 prompt 當參照，問新 prompt 更像哪一邊。

  

  
    
    
  • Jev 真正做不到的未知：它不會發明新標籤、不會寫出新類別的名字。發現新類別的那一步要靠人或生成模型，Jev 負責把值得看的候選挑出來，以及在新類別命名後大量驗證。
    • 
    
  • 可靠的組合是級聯：Jev 大量篩選 → 低信心或 none 的少數交給 LLM 判讀與命名 → Jev 用新問題回頭驗證 LLM 的答案。官方 SDE cascade cookbook 就是這個形狀，成本主要落在少數困難案例。
