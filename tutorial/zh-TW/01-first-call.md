# 第 1 課：第一次呼叫

## 情境

一張信用卡帳單夾在兩則廣告之間掉進收件匣。你知道流程：找金額、找截止日、決定是不是今天的事。每個月都用眼睛做一次，一年漏掉兩次。

**原因：** 資訊就在文字裡，但沒有東西替你讀。**這一課改變什麼：** 你把訊息連同三個問題送給 Jev，拿回提醒 app 能直接用的數字。

**目標：** 只用 `curl`，看清楚送了什麼、回了什麼。

## 做

```sh
sh examples/curl/first-call.sh
```

## 你應該看到

腳本送一個 `state` 和三題。錄下的答案（`examples/expected/curl-first-call.txt`，模型 `jev-1.13.0`）：

```json
{
 "needs_action_today": {"type": "noul",   "noul": 0.12},
 "kind":               {"type": "choice", "choice": "bill", "confidence": 0.99},
 "urgency":            {"type": "score",  "score": 0.6, "confidence": 0.23,
                        "legend": {"0": "can wait a week", "1": "within a few days", "2": "today"}}
}
```

## 注意

- 訊息是中文，問題是英文。這是正常的搭配。
- `noul` 是機率，不是判決。「今天要處理嗎」0.12 讀作「大概不是今天」，這是對的：截止日是 25 號。
- `choice` 回的是選中的選項**加上**每個選項的機率（上面省略）**加上**信心值。`bill` 拿到 0.99 表示沒有別的選項接近。
- `score` 是等級之間的加權位置：0.6 落在「可以等一週」與「幾天內」之間。信心只有 0.23，因為不知道今天幾號，模型真的無法判斷 25 號有多遠。這是誠實的，第 4 課會教你怎麼修：把日期給它。
- 沒有任何散文回來。沒有東西要解析。

## 練習

把腳本裡的 `state` 換成你自己收件匣裡的一則訊息再跑一次。先不要改問題。
